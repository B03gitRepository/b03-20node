# 四组协作入口

第一次接手先按[仓库首页](../README.md)准备赛事方提供的数据和只读分组仿真器，跑默认工单并保存核验结果。20、100 节点使用同一套接口。各组从对应仓库已发布的提交建立自己的分支，在配置中更换组件。系统集成组负责合入两种规模。

| 小组 | 维护范围 | 首次提交通路 |
|---|---|---|
| 模型组 | 读取 RC 已送达的状态、原始业务与优先级，在合法目录内选工具。在线采样交付真实行为概率、版本和可恢复的检查点。 | 按[模型接口](MODEL.md)替换选择器，先跑一张冻结工单。比较动作、U、W、推理用时。低比特 CPU 示例为 `config/int8-model.json`。 |
| 仿真组 | 维护分组队列、观测传输与设备执行，在相同契约下登记新的引擎或适配器。 | 按[仿真接口](SIMULATOR.md)更换 `config/example-simulator.json`。交付报告采样与到达、指令实际生效与读回的时间。 |
| 知识库与规则库组 | 维护知识编号、来源和适用条件，改进路径与联合资源求解。主控负责提供可写范围与预算。 | 按[知识接口](KNOWLEDGE.md)切换 K044 的查询提供者，或按[规则接口](RULES.md)用 `config/branch-rules.json` 运行独立规则 M。一次比较只改一项。 |
| 系统集成组 | 维护 OM/RC、A2A、工单权限、动作目录、唯一设备写入、结果核验和版本发布。 | 在两个规模重跑同条件工单，核对三段时延、连通度、业务保障、设备读回和历史回执，登记通过的提交。 |

**提交给系统集成组的内容**包括组件版本、配置差异、复现命令和一张对照表。表中写明原工单与新方案的动作、U/W、耗时、设备生效和读回数。样本少时写出样本数，未确认的工单保留状态。完整决策输入、业务轨迹和权重放在经授权的协作存储，公开仓提交源码、可共享技术知识和汇总。

规则组可以独立测试新算法。已训练权重配套使用原来的动作语义、映射与预算。拟让模型使用新动作时，先登记新目录，在留出工单对照收益，再由模型组与系统集成组决定是否补训。技术知识不改变原始 QoS 或实时写权限。
